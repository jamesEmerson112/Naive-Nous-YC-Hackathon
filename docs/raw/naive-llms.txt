# Naive

> The managed agent for long-horizon work. Runtime, harness, inference, and tools.

- [Naive docs](https://usenaive.ai/docs/index.md): The most efficient managed agent for long-horizon work. The highest intelligence per dollar, by design.
- [Quickstart](https://usenaive.ai/docs/quickstart.md): Create an agent, give it work, watch it, and read the meter.
- [How Naive Managed Agents works](https://usenaive.ai/docs/how-managed-agents-is-built.md): Three layers — harness, tools, runtime — optimised together for cost per finished task.
- [Examples](https://usenaive.ai/docs/use-cases.md): Three end-to-end examples of long-horizon work on Naive Managed Agents.
- [Agent](https://usenaive.ai/docs/capabilities/agent.md): Naive Managed Agents' core primitive — a versioned config of model, harness, prompt, tools, skills, and budget that runs as durable sessions.
- [Computer](https://usenaive.ai/docs/capabilities/computer.md): Naive Managed Agents' own managed sandbox — a disposable Linux micro-VM with a filesystem, a shell, and an optional browser, paused when the agent sleeps.
- [Identity](https://usenaive.ai/docs/capabilities/identity.md): An addressable persona an agent acts as: email, phone, social accounts, web domains, third-party connections, and a credential vault.
- [Team](https://usenaive.ai/docs/capabilities/team.md): A coordinator agent and a version-pinned roster of specialists, coordinating two ways: point-to-point delegation and a durable shared board.
- [Organizations & members](https://usenaive.ai/docs/platform/organizations.md): The organization is the billing entity; users are members.
- [Credits & billing](https://usenaive.ai/docs/platform/billing.md): A real US-dollar balance, topped up through the payments provider, metered against vendor cost.
- [Pricing](https://usenaive.ai/docs/platform/pricing.md): What you pay, and how the completion window changes it.
- [Agents](https://usenaive.ai/docs/concepts/agents.md): A reusable, versioned configuration that defines an agent's persona and capabilities.
- [Runtime & durability](https://usenaive.ai/docs/concepts/runtime.md): The runtime is Naive Managed Agents' infrastructure, not a setting: wake, take one turn, commit, sleep — and idle costs storage.
- [Harnesses](https://usenaive.ai/docs/concepts/harnesses.md): The agent loop is one field. Which loop you pick changes how the work is done — and what an idle session costs.
- [Harness capabilities](https://usenaive.ai/docs/concepts/harness-capabilities.md): Every harness, and exactly what it can be admitted for: approvals, typed results, streaming deltas, whether the platform's own tools reach the model, and what an idle session holds.
- [Model router & inference](https://usenaive.ai/docs/concepts/model-router.md): How Naive Managed Agents routes each model call to inference — an agent's turn or one you make yourself — what the completion window changes about it, and how model tokens are metered.
- [Model auto-selection](https://usenaive.ai/docs/concepts/model-selection.md): Let an evaluation model choose which of your models answers a conversation.
- [Completion window](https://usenaive.ai/docs/concepts/completion-window.md): Three prices for one model, chosen per request.
- [Budgets](https://usenaive.ai/docs/concepts/budgets.md): Every call is priced before it is made and refused if it would breach the cap.
- [Policies](https://usenaive.ai/docs/concepts/policies.md): Governance at the tool-call boundary: per-tool allow / ask / deny on the agent's toolset.
- [Templates](https://usenaive.ai/docs/concepts/templates.md): A template is a crew with a first day and a memory of the business it runs — chosen from a blueprint, provisioned by an apply.
- [Sessions](https://usenaive.ai/docs/concepts/sessions.md): A single, directly-controlled run of an agent.
- [Session operations](https://usenaive.ai/docs/concepts/session-operations.md): Send input, retrieve, list, interrupt, archive, and delete sessions.
- [Events & streaming](https://usenaive.ai/docs/concepts/events-and-streaming.md): The resumable, sequence-keyed event stream behind every session.
- [Skills](https://usenaive.ai/docs/capabilities/skills.md): Persisted, versioned expertise loaded with progressive disclosure.
- [Tools, connections & context](https://usenaive.ai/docs/capabilities/tools.md): Declare what the agent may use — built-ins, connection tools, and MCP servers — gate each one with a permission, and keep the context window small.
- [Data](https://usenaive.ai/docs/capabilities/data.md): Read data across 18 domains — social media, people, companies, funding, markets, SEO, news, law, weather, jobs, property, reviews, trade, shopping and travel — from an agent, the dashboard, the API, the SDK or the CLI. Priced per run.
- [Social data](https://usenaive.ai/docs/capabilities/social-data.md): Read public posts, profiles, comments, followers, hashtags and trends on about 21 social networks — from an agent, the dashboard, the API, the SDK or the CLI. No connected account; priced per run.
- [Files](https://usenaive.ai/docs/capabilities/files.md): Durable, organization-scoped storage for the artifacts a session produces.
- [3D assets](https://usenaive.ai/docs/capabilities/3d.md): Generate a textured 3D model from a description or photos, or build a dimensioned part or scene in code — two agent tools, one file library.
- [Structured outputs](https://usenaive.ai/docs/capabilities/structured-outputs.md): Constrain a session's final result to a JSON Schema and read it back as typed data — no transcript scraping.
- [Outcomes & graders](https://usenaive.ai/docs/capabilities/outcomes.md): Score a session against a rubric with a model-driven grader loop.
- [Deployments & cron](https://usenaive.ai/docs/capabilities/deployments.md): Run an agent on a schedule, then collect the results of every fire.
- [Webhooks](https://usenaive.ai/docs/capabilities/webhooks.md): Subscribe to session and message events; receive inbound email and SMS.
- [Observability](https://usenaive.ai/docs/capabilities/observability.md): Per-session cost and token usage, a usage event before every idle, and a full trace of every turn, tool call, and model request.
- [Computer](https://usenaive.ai/docs/computer/index.md): Naive Managed Agents' own managed sandbox — a disposable Linux micro-VM with a filesystem, a shell, and an optional browser, paused when the agent sleeps.
- [Sandbox & lifecycle](https://usenaive.ai/docs/computer/sandbox.md): Execution modes, provisioned resources, and the creating → running → paused → destroyed lifecycle of a computer.
- [Filesystem](https://usenaive.ai/docs/computer/filesystem.md): Read, write, list, and manage files on the sandbox disk through five governed operations.
- [Shell](https://usenaive.ai/docs/computer/shell.md): The bash tool runs a command in the sandbox and returns buffered stdout, stderr, and an exit code.
- [Browser](https://usenaive.ai/docs/computer/browser.md): An optional managed browser attached to the computer — domain-scoped, write-guarded, and driven through high-level actions.
- [Mobile device](https://usenaive.ai/docs/computer/mobile.md): A cloud Android phone or iPhone, beside the sandbox and the browser: look at its screen, tap, type, open a link, install an app, watch it live.
- [Snapshots & volumes](https://usenaive.ai/docs/computer/snapshots-and-volumes.md): Checkpoint a running VM and fork new computers from it. Persistent volumes are not available.
- [Networking](https://usenaive.ai/docs/computer/networking.md): Outbound access from the sandbox, and the coming egress pinning.
- [Limits & billing](https://usenaive.ai/docs/computer/limits-and-billing.md): Runtime ceilings, output limits, and the exact metering model for compute.
- [Identity](https://usenaive.ai/docs/identity/overview.md): Named personas an agent acts as: web domains, email, phone, connections, and a credential vault.
- [Personas](https://usenaive.ai/docs/identity/personas.md): The identity object: name, description, the endpoints it owns, and how it attaches to agents.
- [Credential vault](https://usenaive.ai/docs/identity/vault.md): Secrets injected at the network boundary — the agent never sees raw values.
- [Identity policies](https://usenaive.ai/docs/identity/policies.md): How an agent's identity tools are governed: the same per-tool allow / ask / deny as every other tool, enforced at the tool-call boundary.
- [Web domains](https://usenaive.ai/docs/identity/domains.md): The dual-track domain system: independent email and app verification, three registrar kinds, and the readiness gates email sits on.
- [Email](https://usenaive.ai/docs/identity/email.md): Provision inboxes on a verified domain; send credit-checked mail and wake the agent on inbound.
- [Phone](https://usenaive.ai/docs/identity/phone.md): Provision numbers on carrier-registered messaging; send and receive SMS.
- [Connections](https://usenaive.ai/docs/identity/connections.md): Let an agent act through third-party apps — OAuth or API key — without ever touching the token.
- [Social accounts](https://usenaive.ai/docs/identity/social.md): Connect social accounts to a Naive Managed Agents identity and let its agent publish under policy.
- [Legal](https://usenaive.ai/docs/identity/legal.md): Verify the people behind an identity and form a company it can operate as, under policy.
- [KYC](https://usenaive.ai/docs/identity/kyc.md): Hosted identity checks for the people behind an identity. The gate before a company can be formed.
- [Wallet](https://usenaive.ai/docs/identity/wallet.md): A custodied, spend-limited wallet an identity carries so its agent can pay for things in the world.
- [Cards](https://usenaive.ai/docs/identity/cards.md): Prepaid virtual cards an identity buys with organization credits, with a single audited credential reveal.
- [Trading](https://usenaive.ai/docs/identity/trading.md): Connect an identity's own brokerage account, and let its agents trade with a person approving each order.

- [Team](https://usenaive.ai/docs/team/overview.md): Multiagent orchestration on Naive Managed Agents: a coordinator agent and a version-pinned roster, coordinating two ways — point-to-point delegation and a durable shared board.
- [Coordinator](https://usenaive.ai/docs/team/coordinator.md): Declare a team by adding a multiagent coordinator object and a roster of members to an agent's configuration.
- [Delegation](https://usenaive.ai/docs/team/delegation.md): The first of a team's two coordination mechanisms: a point-to-point hand-off through built-in tools, each member running in its own isolated session.
- [Company board](https://usenaive.ai/docs/team/board.md): The durable half of a team: one board owned by the coordinator, shared by every agent on its roster, where a card is the hand-over and assigning a card starts the teammate on it.
